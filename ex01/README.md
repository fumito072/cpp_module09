# ex01 : Reverse Polish Notation（逆ポーランド記法）

## 0. この演習でやること（概要）

「逆ポーランド記法（RPN, Reverse Polish Notation）」で書かれた数式を
コマンドライン引数で受け取り、計算して結果を表示するプログラムです。

```
$ ./RPN "8 9 * 9 - 9 - 9 - 4 - 1 +"
42
$ ./RPN "7 7 * 7 -"
42
$ ./RPN "1 2 * 2 / 2 * 2 4 - +"
0
$ ./RPN "(1 + 1)"
Error
```

計算には `std::stack`（スタック）を使います。

---

## 1. 逆ポーランド記法（RPN）とは

普段書く `3 + 4` のように演算子を数の**間**に置く書き方を「中置記法」と呼びます。
RPN は演算子を数の**後ろ**に置く書き方で、`3 4 +` と書きます。

| 中置記法 | 逆ポーランド記法（RPN） |
|---|---|
| `3 + 4` | `3 4 +` |
| `(1 + 2) * 3` | `1 2 + 3 *` |
| `7 * 7 - 7` | `7 7 * 7 -` |

RPN の利点は「**括弧が要らない**」「**左から順番に計算するだけで答えが出る**」
ことです。だからスタックと非常に相性が良いのです。

---

## 2. なぜ `std::stack` を使うのか

このモジュールは「演習ごとに違うコンテナを使う」縛りがあり、ex00で `std::map` を
使ったので、ex01では `std::stack` を使います。RPN の評価はスタックそのもので、

- 数を見たら **積む（push）**
- 演算子を見たら **2つ降ろして（pop）計算し、結果を積む（push）**

という動きが、スタックの「後入れ先出し（LIFO, Last In First Out）」に完全に一致します。

> `std::stack` は「コンテナアダプタ」と呼ばれ、内部的には別のコンテナ（標準では
> `std::deque`）の上に「`push` / `top` / `pop` / `size` / `empty` しか使えない」
> という制限を被せたものです。今回は途中の値を積むのに使います。

---

## 3. 登場する新しい概念

### 3-1. スタック（LIFO）

最後に入れたものが最初に出てくるデータ構造。皿を積み上げて上から取るイメージ。

- `push(x)` … 上に積む
- `top()` … 一番上を見る（取り出さない）
- `pop()` … 一番上を捨てる（値は返さない）

### 3-2. RPN 評価アルゴリズム

トークン（記号の最小単位）を左から1つずつ処理します。

```
各トークン t について:
  t が数字なら           → push(t)
  t が演算子(+ - * /)なら → b = pop(); a = pop(); push(a 演算 b)
最後にスタックに1個だけ残れば、それが答え。
```

`a` と `b` の順番が重要です。先に積まれた方が `a`、後に積まれた方が `b` で、
`a - b` や `a / b` の順で計算します（引き算・割り算は順番で結果が変わるため）。

### 3-3. トークン処理

入力文字列を `std::istringstream` に流し込み、`>>` で空白区切りのトークンに
分解します。各トークンは「1文字でなければならない」とし、`12`（2桁）や `++` は
不正として弾きます（課題仕様：数字は10未満＝1桁）。

### 3-4. エラー処理

次の状況で例外を投げ、`main` がそれを捕まえて標準エラーに `Error` を出します。

- 不正なトークン（数字でも `+ - * /` でもない、または2文字以上）
- 演算子なのにスタックに2個未満しか無い（オペランド不足）
- ゼロ除算（`5 0 /`）
- 計算後にスタックに1個だけ残らない（数が多すぎ／少なすぎ）

### クラスの主なメンバ

- `evaluate(expression)` … 式を評価して `int` を返す（核心）。
- `isOperator(c)` … 1文字が演算子かどうか（static）。
- `applyOperator(a, b, op)` … `a op b` を計算（static、ゼロ除算で例外）。
- `std::stack<int> _stack` … 計算途中の値を積むスタック。

## 6. コードの詳細解説

### `evaluate` の中身（ステップ追跡）

```cpp
int RPN::evaluate(const std::string& expression)
{
    while (!_stack.empty()) _stack.pop();   // 使い回し対策で空にする

    std::istringstream iss(expression);
    std::string token;
    while (iss >> token)                    // 空白区切りでトークンを取り出す
    {
        if (token.size() != 1)              // 1文字でなければ不正
            throw std::runtime_error("invalid token");
        char c = token[0];

        if (std::isdigit(c))                // 数字 → push
            _stack.push(c - '0');           // '7'-'0' == 7
        else if (isOperator(c))             // 演算子 → 2つ pop して計算
        {
            if (_stack.size() < 2)
                throw std::runtime_error("not enough operands");
            int b = _stack.top(); _stack.pop();   // 後から積んだ方が b
            int a = _stack.top(); _stack.pop();   // 先に積んだ方が a
            _stack.push(applyOperator(a, b, c));  // a op b を積む
        }
        else
            throw std::runtime_error("invalid token");  // 括弧・小数等
    }
    if (_stack.size() != 1)                 // ちょうど1個残らなければ不正
        throw std::runtime_error("invalid expression");
    return (_stack.top());
}
```

### 実際の評価トレース：`"7 7 * 7 -"`

| 読むトークン | 動作 | スタックの状態（下→上） |
|---|---|---|
| `7` | push(7) | `7` |
| `7` | push(7) | `7 7` |
| `*` | b=7, a=7 → push(7*7=49) | `49` |
| `7` | push(7) | `49 7` |
| `-` | b=7, a=49 → push(49-7=42) | `42` |
| （終了） | size==1 → 答え | `42` |

### 実際の評価トレース：`"8 9 * 9 - 9 - 9 - 4 - 1 +"`

```
8 9 *       → 72
72 9 -      → 63
63 9 -      → 54
54 9 -      → 45
45 4 -      → 41
41 1 +      → 42
```

### `a` と `b` の順番が大事な理由

`-` を例にすると、スタックは下から `[a, b]` の順に積まれています。
RPN の `a b -` は中置の `a - b` を意味するので、

```cpp
int b = _stack.top(); _stack.pop();  // 上＝後から積んだ＝右オペランド
int a = _stack.top(); _stack.pop();  // 下＝先に積んだ＝左オペランド
// a - b （a / b）を計算する
```

逆にすると `5 3 -` が `3 - 5 = -2` になり間違います。

### ゼロ除算の処理

```cpp
case '/':
    if (b == 0)
        throw std::runtime_error("division by zero");
    return (a / b);
```

`/` のときだけ右オペランド `b` が0かを確認し、0なら例外。`main` が
`Error` を出します。

## 7. つまずきポイント / 評価で訊かれること（Q&A）

**Q1. なぜスタックなの？**
A. RPN は「数が来たら積む、演算子が来たら2つ降ろして計算して積む」という
処理で、これは LIFO（後入れ先出し）そのものだからです。最後に積んだ2つを
すぐ使うので、上から取り出せるスタックがぴったりです。

**Q2. `(1 + 1)` がなぜ Error なの？**
A. 課題仕様で括弧・中置記法は扱いません。`(` を読んだ時点で「数字でも演算子でも
ない不正トークン」として例外にします。また RPN では括弧は不要です。

**Q3. `pop` の順番を間違えるとどうなる？**
A. `-` と `/` で結果が逆になります（`a-b` が `b-a` に）。`+` と `*` は
交換法則が成り立つので順番を間違えても結果は同じですが、統一して
「上＝b、下＝a」で取り出すのが安全です。

**Q4. 計算途中で10以上になってもいいの？**
A. はい。仕様で「10未満」は**入力に書く数字**の話で、計算途中や結果は
その制限を受けません（`8 9 *` の途中結果72はOK）。

**Q5. オペランド不足やトークン過剰はどう検知している？**
A. 演算子処理の前に `_stack.size() < 2` を確認してオペランド不足を検知。
全トークン処理後に `_stack.size() != 1` を確認して、数が多すぎ／少なすぎを
検知しています。

**Q6. `c - '0'` は何をしている？**
A. 文字 `'7'` の文字コードから `'0'` の文字コードを引くと整数 `7` になります。
ASCII では `'0'〜'9'` が連続しているので成立する、文字→数字の定番テクニックです。
