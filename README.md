# C++ Module 09 — STL（標準テンプレートライブラリ）

このモジュールは C++ の **STL（Standard Template Library）コンテナ**を
実際に使ってプログラムを書く練習です。`std::map`・`std::stack`・`std::vector`・
`std::deque` といった「データの入れ物」を、課題に合わせて選び・使いこなすことが
テーマです。

- **ex00 : Bitcoin Exchange** — `std::map` を使った日付→レートの検索
- **ex01 : Reverse Polish Notation** — `std::stack` を使った数式の評価
- **ex02 : PmergeMe** — `std::vector` と `std::deque` で Ford-Johnson ソート

---

## 0. このモジュール最大の縛り：「演習ごとに違うコンテナを使う」

このモジュールには独特のルールがあります。

> **一度ある演習で使ったコンテナは、このモジュールの残りの演習では使えない。**
> （ex00・ex01・ex02 で、それぞれ異なるコンテナを使うこと。ex02 は2種類使う。）

本リポジトリでの割り当ては次の通りです。

| 演習 | 使うコンテナ | 用途 |
|---|---|---|
| ex00 | `std::map` | 日付（キー）→レート（値）の格納とソート済み検索 |
| ex01 | `std::stack` | RPN（逆ポーランド記法）の計算途中の値を積む |
| ex02 | `std::vector` ＋ `std::deque` | Ford-Johnson ソート（2種類で速度比較） |

### このルールの意味（なぜこんな縛りがあるのか）

STL には用途の違う複数のコンテナがあります。この縛りは
「**どのコンテナがどの場面に向いているかを、実際に使い分けて体で覚える**」
ための仕掛けです。1種類（たとえば `std::vector`）で全部やろうとすれば一応
書けてしまいますが、それでは「適材適所」の感覚が身につきません。
だからわざと「同じコンテナの使い回しを禁止」して、課題ごとに最適なコンテナを
選ばせています。

## 1. 各コンテナの特徴と使い分け（初学者向け）

STL コンテナは大きく「**シーケンスコンテナ**（順番に並べる）」と
「**連想コンテナ**（キーで探す）」と「**コンテナアダプタ**（他のコンテナに
制限を被せたもの）」に分かれます。

### `std::vector`（シーケンス：可変長配列）

- **中身**：1本の連続したメモリ（普通の配列とほぼ同じ）。
- **得意**：`v[i]` のランダムアクセスが O(1)。末尾追加が速い。キャッシュ効率が良い。
- **苦手**：途中への挿入・削除は後ろを全部ずらすので O(N)。
- **使う場面**：とにかく速くまとめて読み書きしたいとき。デフォルトの第一候補。
- 本モジュールでは **ex02** で使用。

### `std::deque`（シーケンス：両端キュー / double-ended queue）

- **中身**：複数の小さなブロックに分割されたメモリ。
- **得意**：**先頭・末尾の両方**への追加・削除が O(1)。`d[i]` も O(1)。
- **苦手**：連続メモリではないぶん、`vector` よりキャッシュ効率が落ちる。
- **使う場面**：両端から出し入れしたいとき。`std::stack`/`std::queue` の土台。
- 本モジュールでは **ex02** で使用（vector と速度比較するため）。

### `std::list`（シーケンス：双方向連結リスト）

- **中身**：各要素が「前後へのポインタ」でつながった鎖。
- **得意**：位置が分かっていれば途中の挿入・削除が O(1)。
- **苦手**：`l[i]` のようなランダムアクセスができない（先頭から辿る O(N)）。
- **使う場面**：頻繁に途中を挿入・削除し、添字アクセスが要らないとき。
- （本リポジトリでは未使用。ex02 で vector/deque を選んだため。）

### `std::map`（連想：キー→値、自動ソート）

- **中身**：赤黒木（平衡二分探索木）。キーで常に昇順に並ぶ。
- **得意**：キーでの検索・挿入・削除が O(log N)。`lower_bound`/`upper_bound` で
  「以上／より大きい」最初の要素を二分探索で取れる。
- **苦手**：連続メモリではないので、ただ順に全部舐めるだけなら vector に劣る。
- **使う場面**：キーで引きたい・常にソートしておきたい・近傍検索したいとき。
- 本モジュールでは **ex00** で使用（日付→レート、`lower_bound` で近傍日付検索）。

### `std::stack`（アダプタ：後入れ先出し / LIFO）

- **中身**：他のコンテナ（標準では `std::deque`）に「`push`/`top`/`pop` だけ」と
  いう制限を被せたもの。
- **得意**：最後に入れたものを最初に取り出す（LIFO）処理。
- **使う場面**：括弧の対応チェック、関数呼び出し、そして RPN の評価。
- 本モジュールでは **ex01** で使用。

### ざっくり選び方チャート

```
キーで引きたい / ソートしておきたい / 近傍検索したい → std::map（連想）
後入れ先出しで積み下ろししたい                       → std::stack（アダプタ）
順番に大量に読み書き、添字アクセス重視               → std::vector
両端から出し入れしたい                               → std::deque
途中の挿入削除が多く添字アクセス不要                 → std::list
```

## 2. 各演習の概要

### ex00 : Bitcoin Exchange（`std::map`）
ビットコイン価格DB（CSV）を `std::map<日付, レート>` に読み込み、入力ファイルの
「日付 | 量」に対して `量 × レート` を表示します。DBに無い日付は、`lower_bound` を
使って「その日付以下で最も近い日付」のレートを使います。
詳細は [`ex00/README.md`](ex00/README.md)。

### ex01 : Reverse Polish Notation（`std::stack`）
逆ポーランド記法（`"7 7 * 7 -"` のような後置記法）の数式を `std::stack` で
評価します。数字は積み、演算子で2つ降ろして計算し結果を積む、を繰り返します。
詳細は [`ex01/README.md`](ex01/README.md)。

### ex02 : PmergeMe（`std::vector` ＋ `std::deque`）
正の整数列を **Ford-Johnson 法（merge-insertion sort）**でソートします。
`std::vector` と `std::deque` の2種類で同じアルゴリズムを実装し、処理時間を
比較します。**このモジュールで最も難しく、READMEも最も詳しく書いています。**
詳細は [`ex02/README.md`](ex02/README.md)。

## 3. 全体のビルド方法

各演習ディレクトリで `make` します（共通の親 Makefile は無し、課題の標準構成）。

```bash
# ex00
cd ex00 && make && ./btc input.txt

# ex01
cd ../ex01 && make && ./RPN "8 9 * 9 - 9 - 9 - 4 - 1 +"

# ex02
cd ../ex02 && make && ./PmergeMe 3 5 9 7 4
```

各 Makefile は `NAME / all / clean / fclean / re` を備え、再リンクを避ける構成です。

評価で使われるコンパイルコマンドと同等のものでも全演習がビルドできます。

```bash
c++ -Wall -Wextra -Werror -std=c++98 *.cpp -o <name>
```

| 演習 | NAME | ビルド成果物 |
|---|---|---|
| ex00 | `btc` | `./btc <input_file>`（`data.csv` を同ディレクトリに置く） |
| ex01 | `RPN` | `./RPN "<RPN式>"` |
| ex02 | `PmergeMe` | `./PmergeMe <正の整数...>` |

---

## 4. 共通ルール（この実装が守っていること）

- **C++98 のみ**（`-std=c++98`）。`-Wall -Wextra -Werror` で警告ゼロ。
- 禁止事項を使用していない：`*printf()`、`*alloc()`/`free()`、`using namespace`、
  `friend`、C++11以降の機能、Boost。
- 全クラスに **OCF（Orthodox Canonical Form：デフォルト/コピー/代入/デストラクタ）**
  を実装。
- 各演習に Makefile（`all/clean/fclean/re`、再リンクしない）。
- **メモリリークなし**（手動の `new`/`delete` を使わず STL コンテナと文字列のみ。
  macOS の `leaks` ツールで全演習 0 leaks を確認済み）。
