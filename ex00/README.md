# ex00 : Bitcoin Exchange

## 0. この演習でやること（概要）

「ビットコインの過去の価格データベース（CSV）」を読み込み、自分が持っている
ビットコインの「量」が、ある日付の時点でいくらの価値になるかを計算するプログラムです。

- 価格DB（`data.csv`）… `日付,レート` の一覧。例: `2011-01-03,0.3`
- 入力ファイル（`input.txt` など）… `日付 | 量` の一覧。例: `2011-01-03 | 3`

入力の各行について、その日付のレートを `data.csv` から探し、`量 × レート` を表示します。

```
$ ./btc input.txt
2011-01-03 => 3 = 0.9          # 量3 × レート0.3 = 0.9
2011-01-03 => 2 = 0.6
...
```

ポイントは「**入力の日付がDBに無いとき、その日付以下で一番近い日付のレートを使う**」
という部分で、ここに `std::map` の `lower_bound` を使います。

---

## 1. なぜ `std::map` を使うのか

このモジュールには「**演習ごとに違うコンテナを使う**」という縛りがあります。
ex00ではこの課題に最も向いている `std::map` を選びました。理由は次の3つです。

1. **キーで自動的にソートされる**
   `std::map<std::string, double>` は、キー（日付の文字列）を入れると
   内部で常に昇順に並べて保持してくれます。日付を `"YYYY-MM-DD"` という
   **固定長・ゼロ埋め**の文字列にしておけば、「文字列の辞書順 ＝ 日付の時系列順」
   になるので、文字列キーのまま正しく時系列で並びます。
   （例: `"2011-01-03" < "2011-01-09" < "2012-01-11"` は文字列比較でも正しい）

2. **`lower_bound` / `upper_bound` が使える**
   ソート済みなので「ある日付以下で最も近い日付」を**二分探索**で高速に探せます。
   これがこの課題の核心です（後述）。

3. **検索が速い**
   `std::map` の内部は赤黒木（平衡二分探索木）で、要素数 N に対して
   1回の検索・挿入が **O(log N)** で済みます。

---

## 2. 登場する新しい概念

### 2-1. `std::map` と二分探索（`lower_bound` / `upper_bound`）

ソート済みコンテナに対して「ある値の位置」を高速に求める操作です。

- `lower_bound(key)` … `key` **以上（>=）** で最初の要素を指すイテレータを返す
- `upper_bound(key)` … `key` **より大きい（>）** 最初の要素を指すイテレータを返す

この演習では `lower_bound` を使って「入力日付ちょうど、または無ければ
それ未満で一番近い日付」を求めます。詳しくは「5. コード詳細解説」で図解します。

### 2-2. CSVパース

`data.csv` の1行は `2011-01-03,0.3` の形です。`,`（カンマ）の位置を
`std::string::find(',')` で探し、前半を日付、後半をレートに切り分けます。
1行目はヘッダ `date,exchange_rate` なので読み飛ばします。

### 2-3. 日付バリデーション（`YYYY-MM-DD`）

ただ「数字が並んでいる」だけでは不十分で、`2001-42-42`（42月42日）のような
あり得ない日付を弾く必要があります。本実装では次を確認します。

- 文字数がちょうど10文字
- 位置4と7が `-`
- それ以外は全て数字
- 月が1〜12、日がその月の日数以内（**うるう年**も考慮）

### 2-4. 文字列→数値変換と桁あふれ（オーバーフロー）検査

入力の「量」は `float` か `0〜1000` の整数です。`std::strtod` で `double` に
変換し、変換後に末尾にゴミ文字が残っていないかを `endptr` で確認します。
さらに `2147483648`（INT_MAX超）のような大きすぎる値は `> 1000` のチェックで
`Error: too large a number.` になります。

## 5. コードの詳細解説（最重要：`lower_bound` 近傍日付ロジック）

入力の日付がDBに**ぴったり存在しない**とき、「その日付以下で最も近い日付」の
レートを使います。たとえばDBに `2011-01-03` と `2011-01-09` しか無いとき、
入力 `2011-01-05` のレートは `2011-01-03`（下の方）のものを使います。

これを `getRate` で次のように実装しています。

```cpp
double BitcoinExchange::getRate(const std::string& date) const
{
    // lower_bound(date) = 「date 以上(>=)で最初の要素」を指すイテレータ
    std::map<std::string,double>::const_iterator it
        = _database.lower_bound(date);

    // (A) 完全一致: it のキーが date と同じならそのレート
    if (it != _database.end() && it->first == date)
        return (it->second);

    // (B) date より小さい日付が1つも無い（= 最古DB日付より前）→ エラー
    if (it == _database.begin())
        throw std::runtime_error("no earlier date in database.");

    // (C) それ以外は一つ前 = 「date 未満で最大の日付」
    --it;
    return (it->second);
}
```

### なぜ `lower_bound` で「下の日付」になるのか（図解）

DBが次のように並んでいるとします（map は自動で昇順）。

```
index:   [0]          [1]          [2]
date :  2011-01-03   2011-01-09   2012-01-11
```

#### ケース1：入力が `2011-01-09`（ぴったり存在）
```
lower_bound("2011-01-09") は「>= 2011-01-09」の最初 = [1] を指す
→ it->first == "2011-01-09" なので完全一致 → [1] のレートを返す
```

#### ケース2：入力が `2011-01-05`（存在しない、間の日付）
```
lower_bound("2011-01-05") は「>= 2011-01-05」の最初 = [1](2011-01-09) を指す
→ it->first != "2011-01-05"（一致しない）
→ it は begin ではない
→ --it して [0](2011-01-03) = 「2011-01-05 未満で最大の日付」 → そのレート
```
ここが核心です。`lower_bound` は「**以上**で最初」を指すので、一致しなければ
**1つ手前**が「自分より小さい中で最大」＝求めたい「下の近傍日付」になります。

#### ケース3：入力が `2030-01-01`（全DB日付より新しい）
```
lower_bound("2030-01-01") は該当なし → end() を指す
→ end() は begin ではないので --it して [2](2012-01-11) = 最新日付 → そのレート
```

#### ケース4：入力が `2000-01-01`（全DB日付より古い）
```
lower_bound("2000-01-01") は [0] を指す（>= の最初）
→ 完全一致でない & it == begin() → 「下の日付が存在しない」→ エラー
```

> **なぜ `upper_bound` ではなく `lower_bound` なのか？**
> `upper_bound(date)` は「date **より大きい**最初」を返すので、完全一致の場合に
> その**次**の日付を指してしまいます。完全一致を優先して取りたいので
> `lower_bound`（>= で最初）を使い、一致判定→ダメなら1つ戻す、という流れが
> 一番自然で正確です。

### 日付バリデーションのうるう年判定

```cpp
bool isLeap = (year % 4 == 0 && (year % 100 != 0 || year % 400 == 0));
```
- 4で割り切れる年はうるう年
- ただし100で割り切れる年は平年（例: 1900）
- ただし400で割り切れる年はうるう年（例: 2000）

これにより `2012-02-29`（うるう年で有効）は通り、`2011-02-29`（平年で無効）は
`Error: bad input` になります。

### 量のパースとオーバーフロー

```cpp
char* endp = NULL;
double v = std::strtod(str.c_str(), &endp);
if (endp == str.c_str() || *endp != '\0')   // 何も変換できない or 末尾にゴミ
    return (false);
```
`std::strtod` は変換できた所までのポインタを `endp` に入れてくれます。
`*endp` が `'\0'` でなければ「`5.5abc` のような不正な値」なので弾きます。
範囲チェック（`< 0`, `> 1000`）は `processLine` 側で行っています。

## 6. つまずきポイント / 評価で訊かれること（Q&A）

**Q1. なぜ日付を文字列のまま map のキーにできるの？整数に変換しなくていいの？**
A. `YYYY-MM-DD` は年4桁・月2桁・日2桁の**固定長ゼロ埋め**なので、文字列の
辞書順比較が日付の時系列順と完全に一致します。だから `std::string` キーのまま
正しくソート・比較できます。逆に `2011-1-3` のような可変長だと崩れます。

**Q2. なぜ `lower_bound` で「下の日付」が取れるの？（最頻出）**
A. `lower_bound(date)` は「date 以上で最初」を指します。完全一致ならそれを使い、
一致しないなら 1つ手前が「date 未満で最大の日付」になるからです。
ケース2の図を見せて説明できればOKです。

**Q3. `std::map` の検索の計算量は？**
A. 内部が赤黒木（平衡二分探索木）なので、検索・挿入・`lower_bound` すべて
**O(log N)** です。線形に全部見る O(N) より圧倒的に速い、と言えます。

**Q4. DBの最古日付より前の入力が来たら？**
A. `lower_bound` が `begin()` を指し完全一致もしないので、「下の日付が無い」
状態です。本実装ではこの行を `Error: bad input` 扱いにしています。

**Q5. `Error: too large a number.` はどう判定している？**
A. 量を `double` に変換し `value > 1000` なら出します。`2147483648`（INT_MAX超）
も `double` なら表現できるので、`int` に入れて溢れさせる必要はなく、単純に
1000超で弾けます。

**Q6. なぜヘッダ行を読み飛ばすの？**
A. `data.csv` の1行目 `date,exchange_rate` と入力の1行目 `date | value` は
データではなく見出しなので、数値変換すると失敗します。1行目だけ特別に
スキップしています。
